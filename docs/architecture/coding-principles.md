# Coding Principles

1. Prefer semantic selectors.
2. Avoid LinkedIn CSS classes when a semantic selector is available.
3. Keep business logic out of `content.js`.
4. Keep modules focused on one responsibility.
5. Keep controllers thin and place business logic in services.
6. Let the store own persistence and scan-session state.
7. Reuse the Scan Store API when exposing dashboard data.
8. Never redesign the public API without a migration path.
9. Investigate before modifying code.
10. Favor small milestones over broad rewrites.
11. Keep verification, extraction, and persistence separate.
12. Treat snapshots and fixtures as contracts, not examples.
13. When a rule is ambiguous, document the decision before changing behavior.
