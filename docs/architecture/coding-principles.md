# Coding Principles

1. Prefer semantic selectors.
2. Avoid LinkedIn CSS classes when a semantic selector is available.
3. Keep business logic out of `content.js`.
4. Keep modules focused on one responsibility.
5. Never redesign the public API without a migration path.
6. Investigate before modifying code.
7. Favor small milestones over broad rewrites.
8. Keep verification, extraction, and persistence separate.
9. Treat snapshots and fixtures as contracts, not examples.
10. When a rule is ambiguous, document the decision before changing behavior.
