# Documentation Rules

1. Every architecture change requires a documentation update first.
2. Every new folder must include a `README.md`.
3. Every module must have a dedicated documentation entry if it participates in runtime behavior.
4. Every feature requires regression testing before merge.
5. Every milestone should produce one focused commit.
6. Documentation must describe the current repository, not desired future behavior.
7. Future roadmap sections must be explicitly labeled as future-only.
8. File-level responsibilities should stay stable unless the code changes.
9. Message types, payloads, and runtime flows must be documented when they change.
10. Test fixtures and snapshots are part of the architecture contract and must be updated deliberately.
